## Automatic machine time zones

- Convert forecasts, reset displays, status checks and response details using the running machine's Windows time zone and the event date's daylight-saving rule. Refresh zone information after a Windows time-zone change.
- Display local-time labels and explicit UTC offsets in details. Preserve stored UTC timestamps and notification fingerprints.
- Use local calendar midnight for DSH daily totals and daily alert deduplication.
- Include a backed-up, offline-only legacy A/B recorder upgrade helper. Remote initialization failures no longer stop local collection, and existing authorization checks remain enforced.

## Timely reset announcements and account quota recovery alerts

- Check immediately on launch, every 60 seconds normally and every 30 seconds with a forecast. Retry feed failures after 15 seconds instead of one hour.
- Recognize short forecast replies such as "Lands tomorrow before 10am PST." Keep relative or community-estimated times advisory.
- Notify about fresh community records even if primary-post verification times out, with an explicit unverified label. Never turn them into confirmed global resets.
- Cache verified primary text against stable feed text, deduplicate across restarts, prioritize the newest notice, and suppress source snapshots older than 15 minutes. The upstream feed normally polls every five minutes.
- Independently alert when consecutive fresh account snapshots show at least a five-percentage-point quota recovery within three minutes. Ignore failed, stale, out-of-order, changed-window and small-jitter samples; do not attribute recovery to a global reset.
- Preserve existing alert preferences, recorder, records, pairing, theme, widget geometry and transparency.

## Output speed now measures generation, not queueing

- Fix the local output tokens/second figure. It divided a response's output tokens by the time since the previous tool result or model response, so silence spent queueing, pacing or waiting on rate limits was charged to the model: a session producing 60-80 tokens per second could be displayed as 3-12, and one throttled session dominated the whole 30-minute window.
- The measured window is now bounded by the model output items the client records for each response. It starts one item duration before the first observed item, that duration comes from the session's own item cadence, and it is only used when at least three plausible gaps exist; otherwise the previous phase anchor is kept, which is the old behaviour.
- Waiting is reported separately as waiting_seconds instead of being counted as generation, and per-response median_tps, excluded_responses and waiting_seconds were added to the local status JSON. Windows shorter than one second, responses below 32 output tokens and physically impossible rates are excluded rather than clamped.
- A response's trailing item is written just after its own usage record; it is no longer mistaken for the first item of the following response, which previously hid that response's waiting.
- Reasoning is still included and explicit tool execution still excluded. This remains an observed generation rate, not pure decode TPS.
- Add three regression tests for pre-first-item waiting, the trailing item and the no-cadence fallback. All 23 probe tests pass.
